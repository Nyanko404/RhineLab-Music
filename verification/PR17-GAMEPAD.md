# PR #17 手柄輸入審查與修復

審查原始提交 `a9cd4bf`，保留貢獻者的實驗性標準手柄支持，并合入 main `af8563b`。

## 發現與處理

- 原實現將無焦點手柄事件派發到 Document，主頁面按鍵處理器訪問 `target.dataset` 時會報錯。改為派發到 body。
- `gamepadConnected()` 被用作 Enter / Home 的事件來源判斷，連接手柄后會搶占實體鍵盤：在設置按鈕上按 Enter 會打開檔案。恢復原有 Enter 焦點規則；僅由本模塊創建的事件才能使用手柄 Home 快捷入口。
- 合成 KeyboardEvent 沒有瀏覽器原生按鈕激活和 Tab 行為。補充 A 激活當前控件、LB / RB 前后移動焦點、彈窗方向鍵移動焦點。長彈窗中允許瀏覽器將焦點控件滾入可見區域。
- 原實現對返回等操作也重復發鍵。B 長按可能先關閉查看器、再退出詳情。僅方向和焦點導航允許重復，確認、返回、搜索、復位按一次觸發一次。
- 斷開手柄后恢復鍵鼠提示，鼠標 / 觸摸操作也會切回提示；查看器 resize 與設備切換共用提示更新，保留觸屏文字。
- Gamepad API 不可用、被策略拒絕或非標準映射時不阻斷頁面；失去焦點后暫停輸入，重新獲得焦點需先松開之前的按鍵。
- main 的彈窗焦點修復與 PR 的格式化產生沖突，已保留 main 的鏈接、禁用狀態和 tabIndex 篩選邏輯。Firefox 音頻修復與網頁渲染優化也隨 main 保留。

## 驗證

`node scripts/check-gamepad-browser.mjs` 在本地 Vite 服務上使用獨立無頭 Edge，模擬標準 Gamepad API 數據，并使用真實鍵盤/鼠標事件驗證混合輸入。支持 `REVIEW_URL` 與 `PLAYWRIGHT_MODULE` 環境變量。

七項行為檢查通過，頁面異常為零：無焦點選檔及 A/B、連接手柄時實體 Enter 打開設置、A 激活按鈕、彈窗方向導航、查看器 resize 保留提示、長按 B 僅關閉當前層、拔出手柄恢復提示。

`npm run build:cloudflare`（含 TypeScript、Vite、PWA、授權字體校驗與靜態打包）、18 項內容檢查、視口檢查、PWA 重定向回歸和 `git diff --check` 通過。構建保留已有的大分塊提示。

本輪沒有真實 USB / 藍牙手柄硬件驗收；仍屬于實驗性標準映射支持。聲音啟動仍受瀏覽器真實用戶激活策略約束，模擬按鍵測試不代表瀏覽器允許手柄解鎖音頻。
