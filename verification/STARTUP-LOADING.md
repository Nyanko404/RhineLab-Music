# 字體分包與開場聲音（GitHub #6、#7）

## 范圍與選擇

用戶于 2026-09-10 批準采用第三方 MiSans 分包，并授權修復后回復、關閉兩個 issue。保留原生實現和既有視覺方向。

對比 npm `misans@4.1.0`（dsrkafuu）和 `misans-webfont@4.3.1`（mobeicanyue），使用開場中英文、40 份檔案的全部文字、四個字重，以及 Chromium canvas 與頁面截圖進行檢查。源碼和分包使用 npm 固定歸檔，未執行上游腳本。

| 四字重合計 | 原整包 | misans | misans-webfont |
| --- | ---: | ---: | ---: |
| 全部字體字節 | 19,744,460 | 8,141,984 | 24,461,284 |
| 同一組開場字符命中分包字節 | 19,744,460 | 1,013,060 | 972,988 |
| 全檔案字符命中分包字節 | 19,744,460 | 2,168,004 | 3,278,460 |

這里的“同一組字符”是向每個字重都請求相同文本的對照，不是實際頁面流量。兩包的 CSS 字符范圍均覆蓋測試語料。

選擇 `misans-webfont`：開場對照稍小，CFF 輪廓渲染更接近現有官方 WOFF2；`misans` 的完整包更小，但其 TrueType 輪廓在逐字柵格對照中變化較多。兩包均基于字體 4.003，現有官方文件為 4.009，因此不聲稱字形逐像素相同。字重固定映射到原來的 300/400/600/700，不使用上游多字體家族/統一 400 的默認 CSS，也不讓設備本地字體覆蓋固定版本。

字體分片原字節保存在 `public/fonts/misans-webfont-4.3.1`；`source.json` 記錄歸檔完整性及每片 SHA-256。上游說明、原 CSS 與字體許可保留。`scripts/vendor-fonts.mjs` 可以從校驗后的 npm 歸檔復現，生成 `src/fonts.css`；沒有現場轉換、重新切字或變更字體輪廓。

## 實際加載與布局

同一 Chrome、1920×1080、禁用 Service Worker 干預的冷頁面測試：

- 原頁面進入前下載四個字體，共 **19,744,460 字節 / 18.83 MiB**。
- 新頁面進入前下載 20 個分片，共 **424,676 字節 / 414.72 KiB**，字體字節減少 **97.85%**。
- 這是字體下載量變化，不是所有網絡、設備上的端到端時間承諾。入口也會等待既有主模型載入和必要字體；音樂下載與準備畫面并行。
- 兩包字體版本帶來少量拉丁字距差別。固定品牌第一行字距調整為 2.324px，中間行 0.587px，三行測量寬度恢復為 **269.78125 / 269.625 / 270px**，與基線一致；字號、字重、行高、起點和 ANALYSIS 的獨立字母定位繼續沿用。
- 1920×1080 的檔案正文寬高仍為 636×660px，未出現橫向溢出。按需字體載入完成后，正文解密遮罩重新測量，保留解密進度。

模型源文件與 Blender 導出路徑保留。Vite 構建為生產模型生成基于 SHA-256 的 URL；版本化字體與模型配置一年 immutable 緩存。模型實際加載仍保持同源，PWA 使用同一版本資源。

完整離線緩存仍包含所有字符分包，避免離線打開新檔案或檢索時缺字；當前完整安裝約 **33.7 MiB / 817 個文件**，比此前約 28 MiB 增大。安裝在用戶進入、聲音準備完成后開始，最多六個并發下載；全部成功后才成為完整版本。任一資源失敗時等待其余下載結束后刪除不完整緩存，保留舊版本。固定版本字體/模型可復用 HTTP 緩存，HTML 與非版本化資源仍驗證更新。

## 開場啟動

- 啟用音效或音樂時，入口停在等待畫面。點擊或觸摸畫面、用按鈕按 Enter/Space 才開始；等待時間不計入動畫，起點仍為原片 6.76 秒。
- 提前下載音樂原始字節；在真實用戶操作中創建或 resume AudioContext，等解碼和必要音軌準備完成，再開始動畫。進入事件不會穿透為跳過動畫或打開檔案。
- 重復點擊不重復啟動。聲音下載失敗、瀏覽器拒絕或等待超時，保留入口并顯示重試；可選擇“關閉聲音并進入”，關閉并保存音效和音樂偏好。取消后遲到的音頻不會自行播放。
- 已關閉兩項聲音的用戶自動進入；動效模式由本站設置控制，啟用聲音時點擊后直接進入檔案。原片定格/場景對照參數繞過入口，不改變時間碼。
- 入口使用實際視口并隔離背景焦點，移動端不把按鈕縮進 1920×1080 舞臺。退出后恢復可見入口按鈕的焦點。

## 檢查與復現

使用本機 Playwright 路徑設置 `PLAYWRIGHT_MODULE`。`npm run build` 生成生產構建；`npm run preview -- --port 5190` 供頁面檢查。

- `scripts/compare-font-packages.mjs`：拆包對照、字重、字符覆蓋、canvas 字寬/像素差與截圖。準備 `.tools/font-comparison/{dsrkafuu,mobeicanyue}/package`；原字體可從先前生產構建或 Git 的 e313777 提取，使用 `BASELINE_FONT_DIR` 指向它。
- `scripts/check-font-loading.mjs`：舊/新生產構建的字體實際下載量、三行品牌寬度、詳情正文尺寸與截圖。通過 `BASELINE_DIST` 指定舊構建。
- `scripts/check-startup-entry.mjs`：桌面、觸摸、鍵盤、減少動態效果、靜音、失敗后重試、連續輸入、取消后遲到音頻、原片定格參數。
- `scripts/check-startup-motion.mjs`：首次進入跟隨瀏覽器動效偏好、本站三種模式、重播與正文解密。
- `scripts/check-pwa.mjs`：完整安裝、離線讀取、顯式更新、收藏/偏好保留與更新失敗。
- `scripts/check-font-update.mjs`：由舊整包字體 PWA 更新到分包版本，刪除舊整包緩存；離線點擊啟動三軌音樂并打開、拆解模型。

最終獨立生產構建的 TypeScript/Vite 構建通過。Chrome 152 與 Edge 152 均通過上述全部入口用例（包括僅音效、僅音樂），當時跨瀏覽器動效環境的完整默認值與重播檢查通過（2026-09-20 已改回首次跟隨系統，見下文）。PWA 完整安裝、離線、失敗回退及從 e313777 整包字體版本遷移到本版的檢查通過，無頁面未捕獲異常。舊緩存更新后，已驗證斷網進入三軌配樂、詳情及模型拆解。檔案內容 18 項檢查與視口計算檢查通過。

Windows Playwright WebKit 26.5 驗證豎屏入口與聲音解碼失敗后的繼續路徑；該環境缺少本項目所需的音頻解碼能力，不能代表 iPhone/Safari 實機音頻驗證。頁面截圖、下載字節與逐項報告輸出在本地 `.tools/issues`，獨立發布檢查輸出在 `.tools/issues-release/.tools/issues`。
