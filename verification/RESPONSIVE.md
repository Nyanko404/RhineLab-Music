# 屏幕比例、觸摸與 PWA 驗證

日期：2026-09-09。保持原生 TypeScript / Three.js / DOM 實現；原片對照繼續使用 1920×1080 舞臺。

## 實現邊界

- 交互舞臺按視口延展；桌面以 1080 高度計算坐標，小屏使用 CSS 像素。寬高比小于 1.05 時采用豎屏布局。
- 豎屏詳情使用上方模型和下方獨立滾動正文；鏡頭構圖只改變投影與相機位置，不移動模型來適配。固定預覽參照保留波浪、抬起和循環軌道的運動。
- 使用安全區域和動態視口；軟鍵盤通過 Visual Viewport 縮短彈窗，不反復重建三維緩沖。橫豎屏切換保留選擇、視角和拆解狀態。
- 指針捕獲、取消和多指隔離避免誤切檔；單次滑動至少 36 px，主軸至少為次軸的 1.3 倍，最長 1.4 秒。查看器雙指縮放與平移，正文保持原生滾動。
- 延用用戶畫質。渲染分辨率按實際畫布尺寸計算；后臺標簽頁暫停更新，開場純二維階段不渲染三維陣列。沒有按手機型號降低材質或陰影。
- Safari 點擊按鈕不一定轉移焦點，因此顯式記錄彈窗與查看器的打開按鈕。缺少全屏 API 時不顯示全屏按鈕。

## 自動檢查

`npm run build`、`npm run check:viewport`、既有檔案內容、循環陣列、解密與畫質檢查均通過。

`scripts/check-responsive.mjs` 在真實 WebGL 頁面驗證以下視口：

| 類型 | CSS 視口 |
| --- | --- |
| 桌面基準 | 1920×1080 |
| 筆記本 | 1440×900 |
| 寬屏 / 超寬屏 | 2560×1080 / 3840×1080 |
| 較方桌面 | 1280×1024 |
| 手機橫屏 / 豎屏 | 844×390 / 390×844 |
| 小屏豎屏 / 橫屏 | 320×568 / 568×320 |

檢查主要按鈕不越界、兩個方向的滑動、八次切檔跨循環接縫、解密完成及抽取高度 4.05、正文滾動和收藏、查看器拆解、雙指縮放和平移、旋轉屏幕后的狀態保留，以及檢索、收藏與設置彈窗。Windows Playwright WebKit 另檢查 390×844、844×390；其指針檢查使用合成 PointerEvent，不能代表 iPhone 真實多指輸入。

1920×1080 原片 39 秒定格與改動前截圖對照：相機、投影與模型坐標一致；RGB 平均絕對差 0.013852 / 255，單通道最大差 4 / 255。截圖為真實渲染差異，不能解釋為所有設備逐像素一致。測試報告和截圖輸出在本地 `.tools/responsive`。

## iPhone 實機

用戶已在 iPhone / Safari 試用并反饋沒有明顯問題。提供 `npm run review:mobile` 與 `reference/mobile-review.html`，可在同一局域網測試陣列、切檔、解密和查看器并保存幀間隔報告；尚未收到真機報告，因此不聲稱已取得 iPhone 幀率或 GPU 耗時數據。Windows WebKit 不支持本次音頻環境，聲音聽感與 iPhone 音頻需以真機為準。

## PWA

`scripts/check-pwa.mjs` 使用生產構建驗證：

- manifest 與圖標；62 個資源、約 28 MiB 的完整版本安裝。
- 斷網重新加載、字體、TXT 導出、模型查看與拆解、音樂資源讀取。
- 新版本等待、用戶明確更新后重啟、清理本應用舊版本、保留其他緩存及收藏偏好。
- 模擬一個圖標返回 503 導致更新失敗：刪除不完整新版本，舊版本繼續離線打開。

這些是本地 Chromium 的 Service Worker 實測。iPhone 從主屏幕啟動、系統安全區、緩存保留時長和音頻自動播放限制，需要實際設備繼續確認。使用步驟與 Vercel 配置見 [PWA 說明](../docs/PWA.md)。
