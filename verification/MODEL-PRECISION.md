# 模型精度三檔對照

2026-09-12。基于 `codex/visual-preserving-performance`，高檔是已經完成上一輪無損渲染優化的版本，不是優化之前的版本。本輪評估“只改變模型幾何精度”的額外收益。

## 檔位

| 模型精度 | 每張背景卡片三角形 | 當前選中／詳情模型三角形 | 處理方式 |
| --- | ---: | ---: | --- |
| 高 | 4,200 | 82,348 | 原始生產模型 |
| 中 | 2,072（減少 50.7%） | 82,348 | 僅背景螺絲、邊框減面 |
| 低 | 1,554（減少 63.0%） | 21,869（減少 73.4%） | 背景進一步減面，近景內環、內構曲面、刻線和螺絲等減面 |

數字來自實際加載到 Three.js 的幾何，包含近景動態標簽平面，不將原資源中生產渲染已排除的 Carbon_Ink 算入。兩個螺絲所屬表面原有 2,136 面，中檔為 384 面，低檔為 148 面。

所有檔位沿用相同分辨率、燈光、材質、玻璃折射、AO、景深、陰影、相機和動作。沒有隱藏螺絲或減少陣列覆蓋，也沒有更換為超級性能模式。蓋板等未簡化表面直接復用原始幾何，不經過 Blender 再導出替換，避免無關的精度變化。

## 實現與復現

- `art/model_precision.py` 通過 Blender MCP 執行，來源為 `public/assets/archive-cassette.glb`；源 SHA256 記錄在 `reference/model-precision/{medium,low}.json`。
- 腳本按自身位置確定倉庫根目錄，支持獨立壁紙倉庫。Blender MCP 中使用 `import runpy; runpy.run_path('實際倉庫路徑/art/model_precision.py', run_name='__main__')`，不將資產寫入另一倉庫。
- `art/model-precision.blend` 保留兩個實驗場景。先合并 glTF 法線／UV 接縫上的重合頂點，再 Decimate，最后從原始模型傳遞法線。首版未合并頂點的低檔產生較明顯分面，已修正；早期 smoke 樣本不作為最終結果。
- `reference/model-precision.ts` 只在對照頁替換指定表面的幾何，保留生產場景的材質對象；中檔近景完全使用原模型。位置包圍盒的偏差過大會直接報錯。
- 對照入口 `reference/model-precision.html` 提供高／中／低、六種場景、亮暗色與暫停，可用 `npm run dev` 在 `/reference/model-precision.html` 打開。
- `node scripts/build-model-precision.mjs` 構建獨立試驗包至 `release/model-precision`。本輪沒有將實驗資產接入正式畫質設置、PWA 資源或創意工坊。

```powershell

node scripts/build-model-precision.mjs
node scripts/check-model-precision.mjs
node scripts/check-model-precision.mjs --host
$env:PNGJS_MODULE='C:/Users/LBLC/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/pngjs'
node scripts/summarize-model-precision.mjs
```

宿主測試使用 Wallpaper Engine 的獨立隱藏測試窗口，名稱為 `Rhine model precision diagnostic`，測試后自動關閉。不會替換正在使用的壁紙。`WALLPAPER_EXE` 可覆蓋可執行文件路徑。瀏覽器與宿主測試順序運行，避免相互占用 GPU。

## 測量方法

本機 RTX 5070 Ti Laptop GPU，ANGLE / D3D11，1920×1080、DPR 1、原始畫質（32 采樣 AO、全分辨率 AO／折射、2048 陰影、景深開啟、SMAA 關閉）。每檔六場景：靜止歸齊、呼吸、連續選檔、穩定詳情、近景旋轉、音樂律動。

三輪順序為高→中→低、低→高→中、中→低→高。每場景先運行相同的 60 幀輸入預熱，再重新穩定并繪制 60 幀，最后記錄 96 幀。匯總使用“每輪中位數的中位數”，同時保留三輪范圍。GPU 時間來自 `EXT_disjoint_timer_query_webgl2`，無效查詢為 null；CPU 時間為 `scene.update()` 同步耗時，不與 GPU 時間相加解釋成端到端幀時間。

固定動畫時間步、隨機核與輸入。自動校驗每檔的相機、選檔、陣列數量、旋轉角度、畫質配置和實例上傳字節一致。逐幀 draw calls 也進行比較：低檔連續選檔在第 76 幀多出 3 次繪制（358→361），兩端三輪均重復出現；這與幾何簡化改變局部包圍球后的邊緣裁剪變化一致，其余幀一致。該例外保存在匯總里，低檔并未靠減少 draw calls 獲得收益。原始采樣和截圖統計見 `model-precision/browser/` 與 `model-precision/host/`。

擴展 TypeScript 檢查（包含三個 reference 腳本）、獨立對照包構建、兩端合計 108 組場景采樣及不變量校驗通過。對照頁的高／中／低切換、詳情旋轉狀態、暗色、暫停和恢復通過實際 Edge 頁面檢查，記錄在 `model-precision/review-check.json`。性能測試結束后才執行對照頁交互檢查，避免額外頁面同時渲染影響采樣。

## 實測結果

GPU 時間單位為 ms，越低越好；括號為相對高檔的下降幅度。

| 場景 | 高 | 中 | 低 |
| --- | ---: | ---: | ---: |
| 陣列呼吸 | 4.682 | 4.279（8.6%） | 4.205（10.2%） |
| 連續選檔 | 5.391 | 5.008（7.1%） | 4.736（12.1%） |
| 近景旋轉 | 5.468 | 4.982（8.9%） | 5.009（8.4%） |
| 音樂律動 | 4.989 | 4.270（14.4%） | 4.124（17.3%） |
| 靜止歸齊／穩定詳情 | 0 | 0 | 0 |

### Wallpaper Engine 原生 CEF（Chrome 146）

| 場景 | 高 | 中 | 低 |
| --- | ---: | ---: | ---: |
| 陣列呼吸 | 4.721 | 4.316（8.6%） | 4.214（10.7%） |
| 連續選檔 | 5.812 | 5.438（6.4%） | 5.308（8.7%） |
| 近景旋轉 | 5.253 | 4.803（8.6%） | 4.650（11.5%） |
| 音樂律動 | 4.686 | 4.254（9.2%） | 4.156（11.3%） |
| 靜止歸齊／穩定詳情 | 0 | 0 | 0 |

本次數據支持模型精度作為額外性能選項，但不支持“面數減少一半就能大幅提高幀率”。中檔在網頁動態場景降低 GPU 耗時約 7%–14%，宿主約 6%–9%；低檔分別約 8%–17% 和 9%–12%。從中檔進一步降到低檔，宿主動態場景僅再降低約 2%–3% 的 GPU 耗時；網頁近景旋轉低檔甚至比中檔稍慢約 0.5%，落在本機采樣波動范圍內。

CPU 沒有一致、明顯的下降。例如宿主陣列呼吸三檔 CPU 中位數都是 2.50ms，連續選檔為 4.20／4.10／3.90ms，音樂為 2.40／2.30／2.50ms。正常動態幀 draw calls 仍為 75，連續選檔中位數仍為 273。模型面數下降不改變像素覆蓋范圍、玻璃折射或后處理次數，這與觀測到的有限收益相符；本輪沒有單獨計時各 Shader 階段，不能據此給它們分配精確成本比例。

幾何的確減少：呼吸場景各渲染通道累計三角形中位數為 4,313,825／2,283,713／1,608,104。該數值包含重復通道繪制，不是場景中唯一三角形數。三檔動畫上傳量相同（呼吸為 20,320 字節／幀）。

推薦先保留高檔作為原畫基準，中檔作為較保守的節能選擇，低檔作為允許細節變化的可選項。低檔的額外視覺代價是否值得，需要用戶在自己的設備上比較；這些測試不代替用戶的視覺確認。

## 視覺與適用范圍

中檔保留完整近景，但背景螺絲和邊框的輪廓／高光有變化。低檔近景的螺絲、刻字、圓環細微邊緣及高光有可見差別；不能稱為逐像素無損。正常尺度與近景旋轉需結合對照頁自行判斷是否接受。首輪陣列呼吸與近景旋轉的高、中、低截圖隨報告保留，其余截圖可由腳本復現。

靜止場景在上一輪優化后已經復用畫面，三檔均無需重復 GPU 繪制，所以降低模型精度不會進一步改善其穩定后的三維繪制成本。仍存在界面、模擬、系統桌面合成等開銷，不能將三維零繪制解釋成壁紙整體零資源占用。

這些是本機數據，不是低配電腦、核顯或真實 iPhone 的結果。顯卡頻率沒有鎖定，測試順序交錯只能減輕溫度、頻率和后臺活動的影響。此次測的是加載完成后的持續渲染，不評價下載時間或峰值內存；實驗頁先加載原模型再替換幾何，不適合作為正式資源加載方案的體積基準。
