# 真實文件夾與玻璃檔案交互

2026-09-10 用戶提出：將當前陣列交互遷移到桌面真實文件夾。當前階段為可行性評估，沒有安裝額外服務或讀取用戶目錄。

## 結論

現有 Three.js 模型與拖動、波浪、抽取交互可以復用。若需要展示普通文件夾的內容，并由系統默認程序打開文件，建議網頁壁紙配合一個本地程序；或將前端裝入桌面應用容器。當前網頁壁紙公開接口不足以單獨承諾完整功能。

Wallpaper Engine 的網頁 directory 屬性支持圖片、視頻目錄，不等于通用文件系統瀏覽。官方 openUserShortcut 文檔屬于 SceneScript，文檔明確只允許在鼠標事件中調用，不能直接當成網頁 JavaScript 接口使用。

## 推薦的后續小范圍試驗

由用戶選擇一個根目錄；每列代表子文件夾、每張玻璃檔案代表文件。選中顯示名稱、類型、大小和修改日期，點擊“打開”調用系統默認程序，另提供“在資源管理器中顯示”。缺失文件有明確提示，目錄改動后刷新。初版不包含刪除、移動、重命名，也不要求接管系統桌面圖標。

本地程序只監聽回環地址，用每次啟動的訪問憑據限制網頁訪問；只允許用戶選定根目錄下的文件，校驗解析后的路徑及鏈接目標，不接受任意命令行。網頁發送文件標識，由本地程序解析已登記路徑后打開。配套程序需要安裝/啟動/退出入口；發布時必須明確它是額外組件。

獨立桌面應用能更完整地支持鍵盤、文件拖放和系統對話框，但嵌入桌面背景、多顯示器與桌面圖標的關系需要單獨實機驗證。不能把普通透明窗口稱作已完成桌面集成。
