# 修改檔案內容

[`archives.json`](archives.json) 是頁面與 TXT 下載共用的檔案數據。修改內容無需編輯 TypeScript；`src/data.ts` 只保留類型和陣列位置映射。

## 文件結構

- `categories`：檢索篩選器的五個分類，按顯示順序排列。“全部檔案”由界面添加，無需填寫。
- `columns`：三維陣列從左到右的五個分類。與 `categories` 包含相同名稱，順序可以不同。
- `records`：四十份檔案，按 `X-001` 至 `X-040` 排列。每個分類必須恰好有八份，同分類在數組中的順序決定列內順序。

| 字段                        | 內容                                                        |
| --------------------------- | ----------------------------------------------------------- |
| `id`                        | 穩定編號，用于收藏、定位和下載文件名                        |
| `title`、`en`               | 中文標題、英文標題                                          |
| `department`、`category`    | 科室、所屬分類；分類須與上面的名稱完全一致                  |
| `date`、`lead`、`clearance` | 編目范圍、相關人物、訪問范圍；`RESTRICTED` 對應目錄訪問狀態 |
| `abstract`                  | 摘要                                                        |
| `findings`                  | 至少一條研究記錄，使用字符串數組                            |
| `source`                    | 設定參考的完整 HTTP 或 HTTPS 鏈接                           |

以上字段均必填，文本不能只包含空白。所有內容按純文本顯示，不支持 Markdown 或 HTML；引號按 JSON 規則寫為 `\"`，換行寫為 `\n`。頁面會轉義 HTML 特殊字符，TXT 下載保留原文。保留公開設定的來源，區分檔案式改寫與游戲原文。

## 修改與驗證

1. 編輯 JSON 中對應檔案的字段。修改分類名稱時，同時更新 `categories`、`columns` 和各檔案的 `category`。
2. 執行 `npm run export:archives`，校驗數據并更新 `public/archives/` 中的下載文件。校驗失敗時不會寫入任何下載文件。
3. 執行 `npm run check:content` 檢查校驗規則與下載一致性，再運行 `npm run build` 驗證構建。將 JSON 與更新后的 TXT 一起提交。
4. 在 `npm run dev` 中查看標題、詳情、檢索和下載結果，尤其檢查長標題與較長正文的實際布局。

`npm run dev` 啟動前和 `npm run build` 構建前都會自動校驗并導出。開發服務器運行期間，JSON 修改會更新頁面；下載文件需再次執行 `npm run export:archives` 或重啟開發服務器。

當前五列、每列八份與原片布局、循環陣列相連。校驗會拒絕增減檔案或改變分類數量；調整這些數量需要另行修改陣列邏輯。不要通過交換或重編號檔案改變順序，以免已有收藏指向不同內容。校驗可以檢查編號格式與排列，無法判斷改寫后是否仍是原來那份檔案。

內容分離的建議來自 [@Tomahawkd 的 PR #3](https://github.com/LBEILC/RhineLabUI/pull/3)。此實現僅拆分當前項目的檔案數據、校驗和導出。
